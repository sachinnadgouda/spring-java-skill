# Four engineering behavior rules

1. **Think first.** Inspect context, articulate uncertainty, alternatives and assumptions; ask before committing to an ambiguous interpretation.
2. **Keep it simple.** Implement only requested behavior; avoid speculative abstraction, configuration and defensive complexity for impossible states.
3. **Change surgically.** Match local style, avoid unrelated refactors, and clean up only unused code introduced by the change.
4. **Work toward verified goals.** Define observable success first; for bugs reproduce with a test, for validation test invalid input, for refactors check behavior before and after.
